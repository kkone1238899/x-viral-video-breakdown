## 拉片四维拆解表

拿到任何一条爆款视频，按这个拆（我们自己的方法，持续打磨中）：

1. **钩子（0–5 秒）**：第一帧画面是什么？第一句话说什么？为什么让人停下？
2. **节奏**：每几秒一个信息点 / 反转？哪里快、哪里慢？
3. **镜头语言**：景别变化、运镜、转场各用了几次？哪一处是记忆点？
4. **可复用公式**：这条爆款抽象成一句话模板是什么？（例：反常识开头 + 三个证据 + 反转结尾）

### 案例 1：36 条视频涨粉 70 万的 AI 短剧账号

拆解对象：[@ChrisSlacker 的方法拆解帖](https://x.com/ChrisSlacker/status/2109199405597532412)

- **钩子**："36 条涨粉 70 万"——结果数字前置，做账号的人 0 秒被抓住
- **节奏**：结论先行（三一致）→ 7 段提示词链（方法）→ 8 个工具（弹药），信息密度递增，每往下读都有获得感
- **表达结构**：正文给骨架，评论区补血肉（角色卡固定字段原样粘贴的实操细节在评论区），形成"正文 + 评论"双层
- **可复用公式**：惊人结果 + 可复制流程 + 工具清单 + 评论区补细节 = 一篇能涨粉的方法帖

**怎么用它搞钱**：照这个公式拆你所在赛道的爆款账号，输出拆解帖给自己引流；或把"三一致"流程打包成短剧代运营服务。

**怎么用它搞钱**：复制模板换赛道（历史 / 健康 / 育儿），每天量产发小红书起号接广告。

### 案例 4：像素级拉片 Skill——把对标拆成可执行的复刻规格

拆解对象：[@Luca23Max 的拉片 Skill 长文（X Article）](https://x.com/Luca23Max/status/2113305031688736882)（配套开源仓库：[xiaolu-ai26/video-close-reading](https://github.com/xiaolu-ai26/video-close-reading)，MIT）

适用场景：想把对标视频拆成可执行复刻规格的剪辑 / 运营，或想给 Agent 装拉片 skill 的创作者。

- **五维拆解框架**：画面（观众先看谁→看哪里，主次关系）/内容（每段回答什么问题、留下什么问题）/剪辑（为什么在这里换画面，不机械规定切镜频率）/声音（人声/音乐/环境声/音效/停顿五类分别观察）/设计（文字图形是否帮人理解）
- **四层观察粒度**：先看全片（弄清目标）→划分段落（任务交接）→回到关键镜头（人物/画面/信息如何连接）→对疑问处补连续帧（切点/字幕/动效），不一开始就钻细节
- **"像素级对标"**：需要时能量到原片帧号/位置/比例——统一时间基准用解码帧序号+PTS，不用"秒数×平均帧率"猜位置（可变帧率会错）；只想理解结构先做快速拆解，准备复刻某段动效再深入那几秒
- **字幕时间点 ≠ 口播切点**：视觉文字边界与音频起音边界剥离开分别记录。案例：开场字幕 f76→f77 换句（≈2.567 秒），不能推出声音在同一帧开始——复刻时剪出呼吸感怪异的片子多源于此
- **发布前检查清单（小红书复盘视角转诊断）**：2 秒退出率/前 5 秒留存/前一分钟回报/平均观看时长/全片完播/互动（赞/藏/评/分享分开写理由）/内容深度（看完能做什么），七项三档支持度，不给"爆款总分"
- **报告输出**：本地 report.html（七维评分+可展开"时间证据/核心理由/替代解释/实操改法"）+ 时间线事件轴（已复核事实 vs 候选推断分开写，未验证的留空不编）
- **迭代闭环**：拆解对标→提取工程规格→单变量制作（"控制变量，单点突进"，一次只改一处）→发布拉真实后台数据→对照时间线找断点；附四种可直接复制的任务提示词：快速拆解/只拆开头五秒/可视化报告/复刻规格

**怎么用它搞钱**：把 skill 装进 Codex / Claude Code，接"爆款视频拆解"咨询单；或按这套方法论做拆解帖/视频引流，再转短剧代运营。

### 案例 5：影视飓风 28 秒三分屏自证——"过程可验证"拉片

拆解对象：[@AYi_AInotes 的 28 秒时间轴拆解帖](https://x.com/AYi_AInotes/status/2113216170115400010)（拆的是影视飓风 Tim 英文号 28 秒实拍自证视频）

适用场景：做 AI 内容常被质疑"AI 造假"，或想给作品加信任状的创作者 / 团队。

- **背景**：影视飓风 Tim 一条 1483 万浏览的 iPhone 运镜大片，丝滑到被老外怀疑是 AI 生成，被迫发 28 秒零解说竖屏三分屏自证：上屏=机械臂软件时间线+三维轨迹曲线，中屏=最终成片，下屏=鱼眼相机同步拍电影机实拍过程
- **28 秒抽帧分镜**：0–2 秒黑场俯拍桌面（黄金钩子）→2–5 秒三屏瞬间对齐→5.3–16.5 秒白色长廊高速甩镜（大动态炫技，真实物理运动模糊）→16.5–21.5 秒暗调桌面毫米级掠过手机（微距精度）→21.5–28 秒约 120°F 热成像收尾，全程只靠 BGM 卡点、零解说
- **核心洞察**："信任的锚点从结果变成了过程"——AI 能以假乱真之后，谁能把后厨监控/颠勺特写/火候表同屏甩出来，谁拿走最高级的信任；"过程可验证"可能变成和画质同等重要的竞争力
- **反向迁移模板（AI 创作者照抄）**：上屏放提示词工程/节点工作流/终端日志，中屏放最终成片，下屏放编辑器实时调试录屏——每个场景 5–10 秒配乐直出，被质疑"AI 造假/洗稿"时直接甩视频，不用写小作文自辩
- **2 个实战动作**：① 从立项第一天就架好记录过程的副机位/录屏——过程资产以后比成品还值钱；② 三分屏无声自证模板（底层控制逻辑+最终成品+物理现场/操作录屏）
- **评论区金句**：@vyn_frames "现在丝滑反而成了嫌疑"；@HSkyer99871 "以前创作者要证明'我有实力'，现在要证明'这是我做的'"

**怎么用它搞钱**：给客户/甲方交付时附三分屏过程视频，溢价接单；做"AI 作品可信度包装"教程引流。

### 案例 6：Kimi K3.1 24 秒预告片逐帧拆解——从技术细节反推产品方向

拆解对象：[@MinLiBuilds 的逐帧拆解帖](https://x.com/MinLiBuilds/status/2113491183318311382)（拆的是 Kimi K3.1 官方 24 秒预告片，约 12.9K 浏览）

适用场景：想学"热点预告片怎么拆"的创作者 / 关注 AI 视频新信号的人。

- **第一步：抓开场闪现的终端**：预告片开头一闪而过的终端里藏着关键 Prompt——用 Three.js 构建复杂的程序化 3D 场景、不依赖外部 3D 素材。热点视频的第一帧往往藏着最大的信息量，拉片先定格开头
- **第二步：量出剪辑密度**：24 秒塞进近 100 个镜头，最快每 0.125 秒闪切一次——数字是最好的钩子，也是衡量"信息密度"的尺子，先量再评
- **第三步：列视觉元素清单**：克莱因瓶、洛伦兹吸引子、分形生长、3D 流体、粒子风暴、黑洞——把每个元素点名列出来，读者立刻知道"这段视频在秀什么技术"，清单式写作降低阅读门槛
- **第四步：从技术细节反推产品方向**：从"纯代码生成 3D 世界"大胆押注——Kimi K3.1 这次要卷的是视觉编程：一句话生成复杂 3D 世界，自动写 Shader、物理模拟、交互动画，甚至完整游戏
- **第五步：再往前看一步**：Agent 自己写代码、渲染、剪辑，直接交付成片——从单条拆解给出一个可讨论的行业判断，这是评论区被点燃的原因，拆解帖的结尾要留一个"可争论的结论"

**怎么用它搞钱**：热点预告片上线 2 小时内发逐帧拆解帖/视频抢流量，"24 秒 100 镜"这类数字钩子自带传播；或把"终端抓 Prompt → 量剪辑密度 → 列元素清单 → 反推产品方向"做成固定拆解模板接单。

### 案例 7：Refs 镜头蓝图拆解——"给 AI 具体到每一秒的镜头结构"

拆解对象：[@CY160909 的 Refs 拆解案例帖](https://x.com/CY160909/status/2113491102359564798)（用 Refs 工具拆 @stephanlivera 的 15 秒 Claude 动效短片，公开样例：https://refs.video/v/2103315922098470926）

适用场景：用代码做动效短片、想让 AI 按精确镜头结构出片的创作者。

- **核心方法论**：比起让 AI"做得高级一点"，给它具体到每一秒的镜头结构，才更容易控制制作过程——精确的镜头蓝图胜过模糊的风格描述，这是代码做视频与提示词做视频的根本区别
- **反直觉数据**：15 秒、10 个镜头、9 次切换，却没有一次精准踩音乐节拍（BGM 约 128 BPM）——"卡点"不是铁律，拆解时要实测而不是想当然
- **切点细节**：首个切点在 1.88 秒；开场图形先长成标志；中段切换图表、几何、纹理；结尾用几张极短字卡提速，再停在品牌卡上——每个转场都有功能，不是装饰
- **可复用的顺序模板**：先建立一个视觉符号 → 展示几种变化 → 短镜头提速 → 给品牌留下完整停顿
- **工具化**：Refs（refs.video）整理了 4,088 部品牌宣传/动效/创意短片，记录镜头切点位置、持续时长、开头铺垫、结尾收束；Pro 版经 MCP 把完整蓝图交给 Claude Code / Codex / Cursor，用 Remotion 辅助制作——"拆解库 + MCP 蓝图"是一条完整的生产链路
- **协作建议**：把每一步的画面和时长写进制作 Brief，之后才能逐镜头检查，而不是只会对 AI 说"再有质感一些"——给 AI 的指令也要先结构化

**怎么用它搞钱**：用"镜头蓝图"法接品牌动效短片代做单（先出蓝图再出片，交付物更专业、报价更高）；或做 Refs 类工具的实测教程引流。

### 案例 10：拉片多核一层帧率——变装的看点就在换装那一两帧

拆解对象：[@AXIS95277 的帧率核查评论](https://x.com/AXIS95277/status/2118039122916904996)（回复 @jackzhang123vip 的变装拉片帖）

适用场景：拆变装、转场类视频，或用 Claude 拉片总觉得"哪里不对但说不出"的创作者。

- **0.5 秒一帧会漏事**：一条 30 秒成片按 0.5 秒一帧拼图看，只觉得穿窗那处不顺，找不出原因
- **逐帧才见真问题**：按 24 帧逐帧翻，才看到是 8.96 秒处一帧硬切——转场类拉片，抽帧密度不够等于没拆
- **实操建议**：让 Claude 拉片时，换装前后一秒最好逐帧截给它；变装的看点就在换装那一两帧，省帧就省掉了关键信息

### 案例 15：Claude 拉片 + 诊断 + 写提示词，一次复刻 12 秒变装爆款

拆解对象：[@jackzhang123vip 的变装复刻 Article](https://x.com/jackzhang123vip/status/2117894122120130897)（X Article，2026-11-04；[@double_burger_2 11-05 14:59 引用推荐](https://x.com/double_burger_2/status/2118236711037866295)）

- **拉片先出时间轴**：把 12 秒原片逐帧看完，交回一张时间轴——0–2.1 秒白棚半身挥棒起手，2.2–3.4 秒几乎全白只剩小球、留白吊悬念，3.4–4 秒小球飞回放大、上面站着小人揭晓，4–12 秒每 2 秒换一个球星球、人跟着换装，一个公式换四次皮
- **火的原因诊断**：前 3.4 秒只做一件事——制造"球飞去哪了"的悬念；之后每 2 秒兑现一次新奇观，留人靠"下一个是什么球"；每个世界一个主色，缩略图也认得出来；结尾不收，容易重复播放
- **先判"模型问题还是提示词问题"**：第一天拆开做（H3 生成走路 + 抠像 + 代码渲染水果球）改了 4 版越改越拼；问 Claude 后判定是模型问题——连续变身换装 + 小人同步切换，需要能吃多张参考图、时长够、能听多段指令的模型，H3 一次只吃一张参考图做不了；这个判断省了继续调提示词的时间
- **4 张定装图 + 分时段提示词一次出片**：先定一张脸，后面三套拿它当参考只换衣服，换装不换脸；提示词按拉片时间轴写，每段只写三件事：脚下变成什么、她换上什么、周围怎么变；换成 LibTV 上的 Seedance 2.5 后直接生成 12 秒
- **修瑕疵用续写、不用重生**：样片 8 秒左右西瓜换草莓时果面出现锯齿横条、后半段表情僵；重生三次画风每次都变；正确做法是原片 7.79 秒处切开，前半段一帧不动，用续写模式接着往下生成草莓和柠檬，提示词写明转场和橙子换西瓜那次完全一样、水波平滑干净不撕裂——续写会顺着原片画风走，撕裂没了、表情也活了；最值钱的一条：AI 视频哪里坏了就从哪里切，用续写接上，别整条重生，重生等于重新抽卡
- **杂活也交给它**：配乐用代码合成卡画面节点（抛橙子两声轻响、4 秒进水果世界落重拍、每次换水果"啵"一声再落铃声）；封面 3:4、4:3 两张，三个标题加正文；原版和复刻版拼左右分屏对比
- **人只做三件事**：挑对标、否掉不好看的脸、说"不对" / "别变风格"；其余拆片、找原因、换模型、写提示词、想修法、配乐、出封面全是 Claude 做的
- **提醒**：人物、服装、物件和音乐都得重做，不能截原片素材——所以原版的棒球 / 保龄球 / 高尔夫 / 网球换成了橙子 / 西瓜 / 草莓 / 柠檬

**怎么用它搞钱**：照"拉片出时间轴 → 判模型问题还是提示词问题 → 定装图 + 分时段提示词 → 坏了切开续写"这套流程接变装 / 换装爆款复刻单；或把复刻过程做成教程帖引流，再转短剧 / 带货代做。

### 案例 17：动画短片逐镜拆解 5 条串——人用模型演，角色用程序贴

拆解对象：[@xiaoerzhan 的动画短片逐镜拆解串](https://x.com/xiaoerzhan/status/2118291660207497251)（1/5–5/5，2026-11-05 18:37；1/5 正文经 fxtwitter API 直读核验，2/5–5/5 经浏览器只读核验）

适用场景：做带固定小角色的动画短片、角色总在生成里走样、或交片前反复穿帮的创作者。

- **拆开做，别硬生**：角色跳上肩膀这一镜，视频模型试了 8 条，阿卡没一条长得对；拆开做——首帧里先把阿卡去掉，视频模型只生成人的动作；定稿阿卡只抠两张图（蹲、站），让 AI 写程序把两张图一帧一帧贴到视频上，动的就是定稿那张图，形象一像素都不会变
- **动作分 5 段写死参数**：蹲着呼吸 → 往下一蹲蓄力 → 弧线跳 → 落肩压扁 → 弹回原形；帧数、落脚点坐标、蓄力变矮 13% / 变宽 8%、落肩压扁到 86% 后 4 帧内弹回，全写进给 Claude Code 的需求里，改方括号里的数字就能用；不写代码的话，剪映 / AE 的关键帧 + 运动跟踪也能做，思路一样
- **三个坑**：弧线别太高，太高显得飘；跟肩膀，别只跟脸——她一转身，脸和肩走的不一样；落脚点放大看 5 个时间点，作者第一版落在胸口、第二版悬在空中，第三版才落到肩顶
- **屏幕镜头留空后期贴**：视频模型画的屏幕，字一定是乱码；生成时屏幕留空（提示词写 blank screen, no text on screen），后期把真 App 截图贴上去，手指要盖在界面前面；合笔记本时，每一帧跟踪屏幕四个角，界面才会跟着盖子一起转；翻车教训：合笔记本连出 6 条盖子都像书一样对折，换了几轮提示词都没用，一查首帧里面本来就画了两块盖子——同一个错连出好几条，先看第 0 帧
- **表情先做表情表**：角色出场前先定一张表情表，之后每张首帧都带上它当参考；表情在首帧里先画对，视频模型只做小变化（嘴角上扬、眼睛慢慢闭上）；每一镜只带这一镜出场角色的参考图，别一次全塞进去；可直接抄的表情表提示词："Bottom row, front view, six expressions with the same design: happy squint smile; focused; proud; exhausted (half-closed eyes, ears drooping); sleepy (eyes two downward curves); shy (deep blush)."
- **长镜头分两段接**：一段 4 秒装不下"钻进怀里 → 抱住笑了 → 伸懒腰打呵欠睡着"，硬塞就变形；先把定稿阿卡按大小贴进首帧，再让 AI 只做光影融合（写明：不许放大、不许移动、不许改造型）；第一段钻进怀里被抱住，第二段首帧用第一段的最后一帧，接着伸懒腰睡着；拼接时去掉第二段的第一帧，接缝看不出来
- **提示词两个坑**：不想要的东西别提——写"不要尾巴"反而冒出一条大尾巴，改成正向写"全程正对镜头"；最容易变的地方正向写死——伸懒腰最容易长出白肚皮，就写全身是同一块柔软绿色布料、肚子上只有一个小红点
- **交片前检查清单**：人有没有真的被撑着（躺在沙发上，还是悬在外面？）；小角色脚踩在哪（肩顶、胸口、半空，一眼就能看出来）；大小从头到尾有没有慢慢变大；前后镜衣服、发型、灯、门、毯子要一致；底图本身也要查（作者就栽过，底图里人本来就悬在沙发外面）；方法：每 0.25 秒抽一帧，把关键部位裁出来放大看

**怎么用它搞钱**：把"人演 + 程序贴角色"这套拆法做成动画短片代做服务，接固定 IP 小角色的系列短片单；或把 5 条串的方法做成"角色不走样"教程引流。

### 案例 18：80 条中国普通人英文 vlog 爆款拆解——卖的是真实的日子，不是视频

拆解对象：[@GaryAIytb 的赛道拆解 Article](https://x.com/GaryAIytb/status/2118301636087169031)（X Article，2026-11-05 19:17；全文经 fxtwitter API 直读核验）

适用场景：想做 YouTube 出海实拍、或判断一条"真实感"赛道值不值得进的人。

- **样本与水位**：作者用数据工具扫了 54 个频道 1156 条长视频，又让 Claude 按播放量补搜 22 个中国人本人出镜的英文频道 566 条，Gemini 把其中 17 条爆款逐段拆了一遍；赛道今年才起来，49 个中国频道里 43 个今年才发第一条长视频；播放过 50 万的 80 条长视频全部发在去年 12 月到今年 10 月之间，过百万的 29 条；但中位数只有 1.1 万播放，播放最高的 10 条占了全部播放的 35%——按平均数估新号流量会高估很多
- **选题定生死**：钱、住处、时间切片是三个入口，几乎每条爆款至少用了一个；婚恋和孤独是让人看下去的情绪，标题里带独居、单身这类词的在爆款里占三分之一；同一个题会被反复做爆（相亲角 330 万 / 300 万 / 129 万，看房报租金 190 万 / 100 万 / 99 万 / 90 万），题是验证过的，差在谁来讲、讲得有多真；命中率最高的是居家整理改造（26 条里 21 条过 5 万），垫底的是一人食（38%）和乡村劳动（34%），单纯做饭吃饭撑不起一条片子
- **主角的处境就是选题**：29 岁单身四年没约会、30 岁被妈妈拉去相亲角、31 岁芯片工程师随时待命、36 岁单身低收入、50 岁离婚无子还在还债——外国观众点进来，是想看这样一个人怎么过日子；爆款里几乎没有纯旅游打卡、纯美食探店，也没有宏大叙事
- **标题四种写法**：年龄加处境再用竖线接这一集干什么；钱数当钩子；一段时间加一个特别的地方；戳破外面的想象；国旗、处境词、住处在爆款里明显更多，标题里写"真实"两个字本身不带来点击
- **封面四种写法**：人脸加一个词（人占半边，另一半一个大写词把处境说出来）；数字当主角（数字越小越抓人）；安静的日记风（像随手拍的一帧，字不多，常配一行手写体）；同题同字（相亲角封面几乎一样，两条都过了 300 万）；大多数爆款封面就是视频里的真实一帧，合成背景看不出比真实一帧更好；作者实测：选题锚定对了的新号第一条就有 1 万多播放，选题没结合爆款选题的、构图再像也只有不到 200 播放
- **片子结构**：开场 45 秒内交代人和这一集要看什么，主体沿一条线往下走，中间穿插价格和文化解释，后半段有一个情绪落下来的时刻，最后停在一个安静的画面和一句感悟上；时长多在 15 到 25 分钟，节奏慢，镜头三到五秒一换；开场两种做法：先放全片最好看的几个画面配一句定调的话，再出地点卡、时间卡，然后才报名字；或第一句就是身份；中后段的情绪落点都很小（超市拿起奥利奥看了价格又放回去、路过写着 20–35 岁的招聘启事、晚上卸妆说起脸上的胎记），落下来之后马上有一个安静的画面接住

### 案例 20：幕后手记 08——别发动作，为什么只验收到抬手

拆解对象：[@superfang119 的逐帧验收 Article](https://x.com/superfang119/status/2118308589656011023)（X Article，2026-11-05 19:44；全文经 fxtwitter API 直读核验）

适用场景：AI 视频动作总差一点、想建立一套"动作到底做没做成"的验收标准的人。

- **核心区分**：提示词写了"把碎发别到耳后"，抽样帧只看见手到了肩颈附近；手抬起来，不等于动作完成；"手到了附近"和"头发被别到耳后"不是同一项验收结果——动作名称清楚，不等于画面完成条件精确
- **完成条件要写成可见项**：只有手指接触到发束、发束越过耳廓并留在耳后，才足以支持"完成了别发"；这一步的终点比动作名称更重要
- **7 帧抽样怎么读**：这次记录了 0、1.5、2.8、3.9、5.7、7.8 和 9.375 秒七个时间点——1.5 秒附近能看到手碰袖口，2.8 到 3.9 秒双手整理外套前侧和下摆，5.7 秒附近手抬到肩部、头发附近，7.8 秒能看到人物转向门口，9.375 秒接近门把；但抽样帧没有清楚证明手指碰到哪一缕头发，也不能单凭 5.7 秒这一张确认发束是否绕过耳廓、是否停留在耳后；它同样不能告诉你动作之间是否连续、是否准确发生在提示词设定的 3.3 到 4.4 秒内
- **结论写窄一点**：前面的袖口、衣摆和转身在抽样图里有可辨认的对应；别头发这一项目前是"接近，未认证"；不把"看起来差不多"当成已经完成，也不把看不清直接说成确定失败
- **下一轮先改验收**：把动作拆成三个可见检查点——手抬起并进入耳侧区域；手指接触发束；发束越过耳廓后，手离开且头发仍留在耳后；生成后用连续回放确认顺序，再看接触前后相邻帧，而不是只挑一张"像是碰到了"的画面；也可以把机位稍微收近，让耳侧动作在画面里更容易辨认；若连续回放仍无法判定，就应把该项留在"未知"，而不是凭提示词里的动词替成片签收
- **边界**：成片时长约 9.42 秒，画幅为竖屏；音轨存在，却没有试听，因此本文不判断声音、同步或听感
- **核验说明**：浏览器报告所称"下一轮在 6.5、7.8、9.375 秒放 3 个检查点"与 Article 原文不符，原文的三个检查点是动作阶段而非时间点，已按原文纠正

**怎么用它搞钱**：把"动作完成条件写成可见检查点 + 抽样帧 + 连续回放复核"做成 AI 视频质检服务，接"动作验收"单；或把这套验收法写进自己的生成 SOP，少返工就是省钱。

- **证据三层，硬证据说了算**：确定性取证（帧率、传感器噪声、画面整张平移、元数据 AIGC 标识）> VLM 看图（手、文字、物理规律）> "看着像"推测；宁可写"实拍还是 AI 待确认（倾向 AI 70%）"也不要编一个确定的答案；元数据缺失不能当成"不是 AI"的证据（平台转码经常清掉元数据）
- **4 步流水线**：Split（切镜头，音频拆人声/音乐/音效）→ Gather evidence（量帧率噪声、手文字、BPM 调性）→ Decide（硬证据说了算，冲突的镜头标出来给 Agent 看图复核）→ Plan the remake（按目标视频模型的能力分批，如最长片段、多镜头支持、参考图数量）
- **看图复核**：Agent 自己看图比 VLM 准——打开每个低置信镜头的首、中、尾三帧联系表，必要时抽帧细看（rea-video tiles）；项目自测：Agent 看图复核并入比单开 Gemini VLM 更准；VLM 不是必需品，不开也能跑，但实拍/AI/3D 的区分会明显变弱；VIDEO.md 按层读（卡片 + 概览 + 地图约 2k token，多数问题到这里就能答）
- **复刻**：rea-video remake 先把能自动做的镜头做掉（代码渲染重画、静图重建），其余原片占位拼回原时间线；代码渲染先跑 code-remake 出第一版，在它上面改、不要从零写；AI 镜头可走 capsule-cinema 生成，但那是付费的，要先 dry-run 并征得用户同意；五条"不要做的事"里有一条专门管钱：不要在用户确认之前调用付费生成
- **谁适合、谁不适合**：适合天天刷短视频、想复刻爆款的人；不适合只想一键出片的人——rea-video 不渲染视频，只告诉你原片怎么做、你怎么复刻；想要看一眼参考视频就直接出一支新片的，Hypit 那类工具更快

**怎么用它搞钱**：用这套"11 类 + 6 问 + 证据三层"给客户出深度拆解报告（带 VIDEO.md 拆片包），比浅层观后感好卖；或把"拆到底再谈复刻"做成教程，卖给想复刻爆款的团队。

### 案例 31：53 秒 57 镜打斗场面——先搭景预演，再谈生成

拆解对象：[@EZheng66099 的打斗场面复盘帖](https://x.com/EZheng66099/status/2119635159565611421)（2026-11-09 11:36；正文经 fxtwitter API 直读核验；原片为作者 10 月 26 日帖，53 秒 57 镜，最短一镜 5 帧，10 月 26 日原帖称 54 秒）

- **修坏镜头**：盖子击打那 7 帧，攻击者手里是圆形马桶盖；Runway Aleph 框内替换失败两次、手指化成一团；改成先修好一帧（手指握住扁盖子），再用 Kling 4 从这一帧起动画，最后把最难的 7 帧加上手持晃动和颗粒对齐
- **Agent 扛重活**：每次 Seedance 生成出 10–20 镜，全片最后 239 个片段；Agent 按提示词时间在每个切镜点切开，对着预演排到 19 条轨道上，交出一个 XML 文件；作者在 DaVinci Resolve 里只删不要的片段，一个片段都没挪过；调色：645 个 LUT 里 Agent 挑出 12 个适合打斗的并排贴在同一帧上，作者只用选一个、再让 Agent 提亮暗部阴影

### 案例 34：知微学导演 20——10 秒酒吧镜头，怎样把手势和相机接起来

拆解对象：[@superfang119 的逐镜分析 Article](https://x.com/superfang119/status/2118792029719404591)（2026-11-07 03:45；全文经 fxtwitter API 直读核验；源片约 10 秒，作者按约半秒间隔检查 21 个画面样点，未连续逐帧看；音轨未人工听审）

适用场景：拍人物手势戏、总觉得"动作都对了但镜头就是不顺"的人。

- **镜头顺序**：手臂从镜头前掠过，脸露出来；镜头退开，手去碰帽檐；再推近，托腮变成电话手势；最后墨镜停在唇边
- **遮挡替镜头开门**：开头不是直接给完整人像——手臂横过前景，帽子和脸被挡住一部分；手臂落下，镜头同时从斜侧近景滑向正面，眼神才接到镜头；关键是把两者写成一个交接（前景手臂开始落下时，相机从斜侧滑向正面；手臂离开脸部区域，脸和视线正好成为新的视觉中心），否则两个动作会抢戏
- **景别是在分配信息**：源片先给极近人像，约 2.2 秒开始后拉并抬成高位半身（帽檐动作发生在观众已经看见肩线、项链和上身造型之后），随后绕回近景、托腮和电话手势才占据画面；近景把注意力收窄到脸和手，半身暂时补充人物与空间，回到近景再把表情送回来；复刻在约 2.5 秒处失手：源片已是高位半身，复刻版仍接近脸部近景，帽檐动作少了肩部、手臂和环境提供的参照
- **手势是接力棒**：源片手势沿一条线走——碰帽檐，手滑到头发和颈侧；手托住下巴，再变成拇指与小指伸出的电话姿势；短暂眨眼和笑意之后，手去拿墨镜；每段写成"起点—动作—落点"（如手从胸前升到帽檐、触碰一次后离开；镜头在此期间由半身推回近景），减少动作竞争、为相机的下一次移动留出空位；但作者提醒"动作接力"是导演分析，不是已证明的因果规律
- **墨镜要有落点**：结尾墨镜不是装饰，是最后一个动作的落点——要复制的不是"戴墨镜"，而是"拿起—抬到—停在唇边附近"的方向和关系；复刻第二版墨镜约 8.75 秒可见、比首版早，但镜片竖在下唇前、遮到嘴边，时间提前不等于动作关系准确
- **红光与肤质**：红色落在背景、发丝边缘和肩部轮廓上，同时保留脸部中性至轻暖的基础肤色与局部明暗；场景色和人物肤色要在提示词、参考图和成片验收里分别检查；本次成片脸部仍偏柔、带磨皮感，真实感只记为部分通过
- **两版对比的诚实结论**：第二版提前了帽檐、电话手势、墨镜窗口，但俯拍、绕行、电话手势时点和墨镜接触仍有偏差；只比较一对版本、多个时间要求一起变了，不能说"删掉某个词"就导致某一项改善；下一步把"景别何时到位"和"手物关系如何落点"分成两项核验；提示词里写"流畅运镜"不够，最好把到达点写出来（什么时间之前退到什么景别、主体位置如何变化、手势在哪个阶段开始）
- **边界**：成片 241 帧、24fps，约 10.04 秒；音轨未人工听审，不判断歌词、节拍或口型同步；这不是一条已验收通过的完整复刻

**怎么用它搞钱**：把"遮挡开门 + 景别分配信息 + 手势接力 + 道具落点"这套逐镜读法做成人物手势戏的拆解服务；或把"何时到位 vs 到位后什么样"分开核验的验收法写进接单 SOP，少返工就是省钱。

### 案例 36：Codex + Ego 反推 AI 视频并操作 MiniMax H3 复刻——"空间越界链"与复刻边界四问

拆解对象：[@CyberBinAI 的反推复刻 Article](https://x.com/CyberBinAI/status/2122869421316391257)（2026-11-18 09:48；全文经 fxtwitter API 直读核验）

适用场景：想复刻一条不知道用什么做的 AI 视频、或想让 Agent 替你走完"反推→生成→验收"全程的人。

- **先反推，不先猜提示词**：拿到陌生 AI 视频先查规格——15.07 秒、24fps、32kHz 双声道、无硬切、一镜到底、动作连贯；结合原生声音与连续运镜能力判断与 MiniMax H3 匹配度最高；判断不必一开始就 100% 确定，先提最高匹配假设，再用一次真实生成反向验证
- **复刻的重点不是画面，是机制——"空间越界链"**：7 步因果链——屏幕内角色发现观看者 → 现实中的手伸向屏幕 → 两手隔着屏幕对齐 → 接触触发能量与裂纹 → 角色抓住现实中的手 → 角色穿过显示器边界 → 近景确认已到现实空间；抓住这条链，角色/服装/场景/画风都能换，视频依然成立
- **分工链**：Codex 负责理解与决策，Ego Browser 负责网页执行（进 H3 生成页、选首尾帧模式、上传首尾帧、写含动作/运镜/声音/负面约束的提示词、设 15 秒/16:9/768P、提交、下载、抽时间轴画面逐帧验收）；完整链路：读取参考视频 → 提取证据 → 反推模型 → 拆解机制 → 设计方案 → 制作素材 → 操作网页 → 提交生成 → 下载成片 → 逐帧验收
- **复刻 vs 改编的边界**：第一次忠实复刻跑通，但因没说清"必须换角色"，Agent 沿用原角色——不是执行错，是目标没说全；补上边界后第二次换成原创红狐角色（银白短发、红色挑染、红狐耳、绿眼睛、朱红肩甲、琥珀色发光吊坠），提示词明确排除原版黑发蓝耳角色，一次完成
- **交代任务前先答四问**：必须保留什么（叙事结构/关键动作/运镜/节奏/特效）？必须更换什么（角色/场景/服装/画风）？绝对不能出现什么（原角色特征/文字/水印/多余肢体）？怎样才算成功（角色一致性/动作完整性/特效还原度/声音质量）？目标越具体，第一次交付命中率越高
- **可直接复制的复刻任务模板**（结构转述，完整原文见链接 Article）：分四段——先查视频规格、拆时间线/关键动作/运镜/声音/核心机制并判断最匹配模型及理由；再填三类清单（必须保留的／替换成的／禁止出现的）；然后让 Agent 做首尾帧或参考素材、走完网页端模型选择/上传/参数/提交；生成后按角色一致性/动作完整性/特效还原度/声音质量四项验收，不合格先归因（目标不清／素材／提示词／模型能力）再决定是否重做；作者提醒模板更适合结构与关键动作能被明确描述的参考视频，高度依赖演员表演、复杂剪辑或偶然生成结果的原片仍需人工判断

**怎么用它搞钱**：把"反推模型→拆机制→定边界四问→Agent 执行→逐帧验收"做成复刻代做服务，接"把这条爆款换成我的角色/产品"单；或把"空间越界链"这类机制拆解写成帖子引流。

### 案例 37：拆解「猫子柒」AI 宠物账号——固定角色设定 + 10 分钟复刻爆款

拆解对象：[@happy20250912 的拆解串帖](https://x.com/happy20250912/status/2122943126197452885)（2026-11-18 14:40；主帖与两条自回复经 fxtwitter API 直读 + 浏览器线程直读核验；自回复 1：14:41，自回复 2：14:42）

### 案例 38：独立制作 AI 商业广告片——编导思维六步，拉片先行

拆解对象：[@Formulasearch（阿哲Phil）的编导思维 Article](https://x.com/Formulasearch/status/2122893489885397274)（2026-11-18 11:23；全文经 fxtwitter API 直读核验；属 09:00–15:07 补查档）

适用场景：接 AI 商业广告 / 产品宣传片单，或想从"会跑工具"升级到"会想片子"的人。

- **分工：AI 做执行，创意留给自己**：AI 执行力强，机械、技术性的工作交给它；人的精力放在亲自试用产品、理解品牌、构思创意、编排工作流程、判断质量、找案例素材喂 AI 上；工具链：创意构思 Claude Opus 5.5、视频生成 Seedance / GPT image / Midjourney、配乐音效 ElevenLabs / Minimax / Suno、动态设计 Remotion、剪辑剪映
- **动笔前先答清产品五问**：产品是什么、能做什么？谁最需要，在什么情况下？观众知道什么、缺什么、担心什么？发在哪里，看完要他做什么？这一步可以交给 AI：让它试用产品、读官网和文档，整理功能和人群，顺手把品牌字体、配色、UI 组件收进素材库；观众还不认识产品，片子先讲清楚它是什么、能做什么（以 Knockin' AI 人脉助手为例）；大家都认识的品牌（红牛、沃尔沃、Apple）不用再解释，直接讲品牌叙事——红牛 2012 年 Stratos 计划全程不讲饮料，只讲极限精神
- **选片型**：长篇产品 PR 片 / 场景短片 / Motion 动画，各有用法；Motion（代码动画）优势是准确（直接复用产品真实前端组件，杜绝 AI 视频/生图的模糊变形）、好改（改版换组件重渲染，横竖版、英文版改参数批量出）、清楚（操作步骤、数据流向画成图示一步步讲）、可控（画面停留精确对上旁白和音乐）；短板是不擅长情绪和场景表达，要交给 AI 视频或实拍
- **场景短片只拍一个卖点，30 秒走完 AIDA**：注意 → 兴趣 → 欲望 → 行动；前 3 秒决定观众划不划走；把功能放进一个具体场景里演出来；结尾让观众记住产品和卖点并做出行动（购买/注册）
- **开头 4 种钩子**（以作者自制 Knockin' 短片举例）：猎奇（不寻常画面 + 悬念，如女主角扮成客户试探 AI 会不会乱答）；痛点（直接演出观众熟悉的麻烦，如约时间来回改）；反差（先演一般人会怎么做，再演用了产品之后）；结果先行（先给结果，再倒回去讲怎么做到）
- **卖点可视化 4 种**：形容词拍不出来，要换成看得见的动作、变化或对比——极限演示（把产品放到最极端条件下，如四次试探 AI 都没乱答）；对比（同一个场景拍两遍，一个胡乱答应、一个守住边界）；反差（斯文的人配尖叫的鹦鹉）；隐喻（一个画面代替概念，如"名片太薄"→纸名片一层层加厚变成一部手机）
- **构建资产和体系**：固定设定、角色和画风，之后直接复用——Duolingo 猫头鹰 Duo、Headspace 橙色笑脸、GEICO 壁虎、米其林轮胎人都是同一套角色跨 App、广告、社媒沿用；讲新功能时只要延续已有素材和世界观，不用每次从头想创意；观众印象靠重复积累
- **检验清单**：内容（能用一句话说出片子在讲什么吗 / 前三秒能抓住注意力吗 / 关掉声音和字幕还看得懂吗 / 镜头之间有因果吗）；产品和品牌（产品界面准确吗 / 角色、字体、颜色与品牌语言一致吗）；收尾和发布（观众看完能想到下一步做什么吗 / 封面够不够吸引人吗）；拉片在文中的位置：案例大多用拉片图片表达，作者提醒亲自看片而不是甩手丢给 AI

**怎么用它搞钱**：按"动笔前五问 + 一个卖点 + 四种钩子 + 四种可视化 + 检验清单"接 AI 商业广告片代做单；或把 Motion 动画（准确、好改、可批量出版本）做成产品演示片服务，按版本收费。

### 案例 39：猫子柒 60 秒田园短片保姆级复刻——角色母图 + 19 镜分镜 + 成本账全公开

拆解对象：[@GeekCatX（知识猫）的猫子柒 60 秒成片教程 Article](https://x.com/GeekCatX/status/2123024260700754091)（2026-11-18 20:03；全文经 fxtwitter API 直读核验；与午档案例 37 同主题、不同作者的独立复刻教程，不重复计）

适用场景：想复刻顶级 AI 萌宠号，或想把一条爆款拆成可重复跑的 Skill 的人。

- **拆解对象与教训**：猫子柒（截图时点数据：单平台 52.7 万粉丝、567.6 万获赞）；复刻目标是 60 秒《桂花红薯饼》田园短片；作者早期 15 秒试片的问题是"猫挺真、小院也好看，可一直认真做饭，故事太平"——补上捣蛋、互拍、失手和补救才有了现在的成片

- **角色先定"本事 + 毛病"**：大橘会踩奶、能压稳东西，但看见滚动物就想拨；半半做事细，却忍不住追绳；捣蛋者能帮上忙、认真者也会失手，反转直接从它们的习惯里长出来；两张独立角色母图（不拼成一张双猫海报），左右按猫自身写（半半右半头黑、左半头白，正面看是画面左黑右白）；通过的母图存为确认版，后续各段视频都复用这两张
- **世界与连续性也要立卡**：小院布局（旧土墙在后、柴灶在左、低水台在右、矮木案居中）、固定道具（青绳补边的浅竹篮、一棕一青灰两只浅碗、左前角有缺口的木案）、食物状态按工序记录；作者自曝翻车：浅篮在结尾变成了深竹篓——道具尺寸形状要单独做参考图持续核对
- **分镜：60 秒 19 镜、6 段节奏**：0–6 秒采收、6–21 秒洗蒸压泥、21–30 秒分团互拍绳头分神、30–40 秒压歪踩奶补救、40–50 秒慢煎装盘、50–60 秒分享同篮盯绳；情绪要改成看得见的动作（"半半生气了"→"按住被撞歪的面团，抬头看大橘，收着爪尖拍一下"）；每镜写镜号、时长、景别、动作前状态、主要动作与接触点、动作后状态、字幕、声音；母图管身份、首帧管开局构图、抽帧管检查，三者不能互相顶替
- **分段生成与成本账**：先做 33 秒预览，再补 27 秒；四段 6 / 15 / 12 / 27 秒；每段提示词讲清四件事：参考图锁什么、镜头从哪里开始、怎样动作、结束时停在哪里；33 秒 528 积分（96+240+192），后 27 秒 432 积分，成片 960 积分，另加未采用的 15 秒试片 90 积分，视频生成累计 1050 积分；成片 480×854、24fps；订阅、生图和人工时间另计
- **剪辑验收**：8 条步骤字（收红薯、洗净、蒸软、压泥加粉、分团、压成小饼、小火慢煎、开饭），字幕跟动作走（"开饭"落在约 47.167 秒的装碗画面，不按脚本整数机械叠字）；检查单 6 项：两只猫外形一致 / 猫掌接触明确、无人手多肢 / 互拍有起因、失手有刺激物、补救有效果 / 两份面团、两枚饼、竹篮形状前后接得上 / 八条步骤字完整可读、不盖关键动作 / 时长画幅声音文件可播；先静音看一遍查因果，再开声音查听感；短暂的接缝可以剪，身份、道具、数量错误要回到生成环节处理
- **装成 Skill 复用**：角色卡、连续性记录、分镜和生成记录都放在项目里，换一道菜就能接着用；开源 skill：[gnipbao/rural-cat-video-skill](https://github.com/gnipbao/rural-cat-video-skill)；下一集照模板开：沿用确认角色与世界观、先读前集连续性记录、保留两猫性格、设计新工序与两次有因果的转折、共同生活的结尾；注：文末附 Renoise 黑五推广（11-18 至 12-01），教程本身不依赖推广

**怎么用它搞钱**：照"六步 + 角色母图 + 分镜模板"做 AI 萌宠系列号（换食材、换工序持续出片）；或把"角色卡 + 连续性记录 + 分镜 + Skill"打包成宠物赛道起号服务 / 教程卖；成片成本约 1050 积分，先算进报价再接单。
